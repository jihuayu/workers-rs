# Plan: RPC stub forwarding

## 背景

`workers-rs` README 把 “Stub forwarding” 标记为 RPC 未完整支持项。

## 目标

实现 RPC stub 在服务间可安全转发，使中间层 worker 可以透明代理下游 RPC 能力。

## 设计

1. 定义 stub 可转发表示：包含目标标识、能力边界、可选元数据。
2. 序列化层支持把 stub 作为参数/返回值安全传递。
3. 转发时保持调用者上下文与错误链路可追踪。
4. 设定安全策略：限制跨命名空间滥用，防止越权转发。

## 需要做的工作

1. 制定 stub 表示协议和版本字段。
2. 扩展 `worker-codegen` 与 runtime glue，支持 stub 编解码。
3. 在 server/client 侧增加转发 helper。
4. 增加测试：
5. A -> B -> C 的多跳转发成功路径。
6. 非法目标或过期 stub 错误路径。
7. 文档补充“转发限制与安全建议”。

## 风险与依赖

1. 安全边界不清晰时容易形成能力泄漏。
2. 多跳转发会增大调试复杂度，需要链路追踪字段。

## 验收标准

1. 支持跨服务转发并保持可观测错误信息。
2. 安全策略有默认保护，且可配置。
3. README 中该缺口可被关闭或明确降级为实验特性。
